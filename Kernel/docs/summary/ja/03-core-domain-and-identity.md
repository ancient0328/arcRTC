# 第03章 core-domain-and-identity

状態: SSOT 統合版
日付: 2026-06-28 JST

## 目的

本章は arcRTC v0.2 Kernel の core における DDD domain model、aggregate、domain service、application use case の境界、core-owned identity / reference、外部 identity との分離、correlation、および Signaling / SFU / TURN / ICE / secure media をまたぐ cross-plane の identity / session binding semantics を、再現実装可能な粒度で内在化します。本章は実装 class / struct の確定ではなく、core 内で混在させてはならない責務と不変条件を固定します。

依存方向の記法は `A <- B` を「B が A に依存」と読みます。本 Kernel の層構造は `core <- drivers <- entrypoints` であり、core は external I/O に依存しません。

## 1. core の所有境界

core は次を所有します。

- domain value object
- aggregate state
- domain service
- application use case
- core-owned port contract
- command / decision / event semantics
- 閉集合 reason vocabulary への接続

core は次を所有しません（禁止）。external I/O、driver implementation、runtime、framework、DB、cloud SDK、browser/native 型。これらは driver または entrypoints に属します。

## 2. 戦術的 DDD の所有規則

| Element | Owner | 規則 |
|---|---|---|
| Value object | core | immutable semantics、equality、validation rule を持つ |
| Aggregate | core | state transition と invariant を持つ |
| Domain service | core | single aggregate に閉じない domain rule を持つ |
| Application use case | core | command orchestration、port 呼び出し、decision emission を持つ |
| Port | core | external implementation への抽象境界を持つ |
| Driver implementation | drivers | port を実装し、external type conversion と I/O を持つ |
| Composition root | entrypoints | implementation selection と dependency wiring だけを持つ |

## 3. 許可される aggregate family

v0.2 初期 architecture で許可する aggregate family は次に限定します。新規 aggregate family は実装前に仕様で導入しなければなりません。

| Family | Scope |
|---|---|
| Signaling room / participant | room state、participant state、command acceptance |
| SFU session / endpoint / route | media routing state と forwarding decision |
| TURN allocation / permission / channel bind | relay authorization lifecycle |
| Cross-plane binding scope | Signaling participant、SFU endpoint/session、TURN allocation/permission、ICE、secure media references 間の関係 |
| Audit chain scope | audit event ordering と hash-chain semantics |
| Configuration scope | startup / wiring policy acceptance |

## 4. application use case 規則

application use case は次の順序で動作します。

1. driver から core-owned command を受け取る。
2. command の correlation / identity / idempotency / replay / version を検証する。
3. aggregate または domain service に decision を委譲する。
4. decision reason を閉集合 reason catalog に接続する。
5. 必要な port command、audit event、external response model を生成する。

application use case は external concrete type を受け取りません。application use case は driver-local retry、socket read/write、DB transaction、runtime task scheduling を所有しません。application use case の result shape は core-owned の結果形状（第04章で内在化する `UseCaseDecision` 等）に従わなければなりません。

## 5. domain service 規則

domain service は pure domain rule のみを持ちます。domain service が port を呼び出す場合、その呼び出しは application use case から明示的に注入された core-owned port contract に限定します。domain service が driver concrete implementation、runtime handle、DB connection、network socket を直接参照することは禁止します。

## 6. validation の所有境界

| Validation | Owner | 例 |
|---|---|---|
| wire shape / decode | driver | JSON field presence、frame size、external enum mapping |
| identity / version / correlation | core | CorrelationId、command version、opaque reference stability |
| idempotency / replay | core | command identity、duplicate handling、replay window |
| domain invariant | core | room accepting join、route selectable、allocation active |
| external implementation readiness | driver/entrypoints | socket bind、DB DSN、exporter initialization |

driver は external shape validation と conversion validation を行います。core は domain validation と policy validation を行います。

## 7. identity 原則

arcRTC core が扱う identity は communication transport のための opaque reference です。core identity から本人性、職能、医療ロール、業務ロール、tenant 権限を推測してはなりません。core は user account、application user identity、regulated identity を定義しません。

## 8. core-owned identity 型

| Type | Owner | Generated by | Lifetime | External exposure | 意味 |
|---|---|---|---|---|---|
| `CorrelationId` | core | driver 生成の untrusted input または core policy。core validation 後のみ受理 | single command / event chain | yes | request / event trace |
| `RoomId` | core | caller 提供の untrusted reference。core validation と wrapping 後のみ受理 | room lifecycle | yes | signaling room reference |
| `SessionId` | core | core policy | transport session lifecycle | yes | communication session reference |
| `ParticipantId` | core | core policy | room membership lifecycle | yes | opaque participant reference |
| `EndpointId` | core | core policy | SFU endpoint lifecycle | internal または controlled external | SFU endpoint reference |
| `StreamId` | core | core policy | media stream lifecycle | 明示的 Signaling/SFU contract を通じた controlled external のみ | opaque media stream reference |
| `PacketId` | core | driver 生成の untrusted input または core policy。core validation 後のみ受理 | packet lifecycle | 既定で no | packet decision correlation |
| `RouteId` | core | core policy | route decision lifecycle | 既定で no | SFU routing decision reference |
| `AllocationId` | core | core policy | TURN allocation lifecycle | 既定で no | TURN allocation reference |
| `PermissionId` | core | core policy | TURN permission lifecycle | 既定で no | TURN permission reference |
| `ChannelBindId` | core | core policy | TURN channel bind lifecycle | 既定で no | TURN channel binding reference |
| `AuditEventId` | core | core policy | audit event lifecycle | audit については yes | audit event reference |
| `CredentialRef` | core | external credential からの driver conversion | credential verification lifecycle | raw secret exposure なし | credential reference のみ |
| `StartupRunId` | core | entrypoints 提供の untrusted startup reference。core validation 後のみ受理、または core policy | single startup / wiring attempt | audit のみ | startup execution reference |
| `ConfigurationScopeRef` | core | entrypoints 提供の untrusted configuration scope。core validation 後のみ受理、または core policy | configuration validation lifecycle | audit のみ | opaque configuration scope reference |

admission scope（rate limit / quota）は core-owned opaque reference を用い、これらの reference から tenant/user/entrypoint role identity を推測してはなりません。authorization context は typed policy input を寄与できますが、trusted core identity の意味を再定義してはなりません。

## 9. client input 規則

client 提供の identifier は untrusted input です。client input は `RoomId` を要求したり external reference を運んだりできますが、core validation と core-owned wrapping を経るまで trusted identity にはなりません。

禁止:

- client 提供 participant ID を trusted `ParticipantId` として扱う。
- token subject を `ParticipantId` と同一視する。
- entrypoint user ID を transport identity と同一視する。
- regulated subject ID を generic communication identity と同一視する。

## 10. opaque reference 規則

external exposure される core identity は opaque でなければなりません。opaque reference は次を含んではなりません。user role、tenant role、medical role、facility identity、personally identifying payload、token secret、media payload information。

## 11. external exposure 規則

core identity の external exposure は public contract surface ごとに明示的でなければなりません。

| Type | Public exposure 規則 |
|---|---|
| `RoomId` | opaque Signaling room reference としてのみ exposure |
| `ParticipantId` | opaque room participant reference としてのみ exposure |
| `SessionId` | opaque communication session reference としてのみ exposure |
| `StreamId` | Signaling/SFU contract が明示的に opaque media stream reference を必要とするときのみ exposure |
| `EndpointId` | 既定では public ではない。controlled operational exposure のみ |
| `PacketId` | 既定では public ではない。明示的に許可された場合の diagnostic/audit correlation のみ |

`StreamId` は media payload type、codec、participant role、tenant、regulated subject、application user identity をエンコードしてはなりません。

## 12. stability 規則（lifetime と reuse）

identity は lifetime 内で stable です。lifetime を超えた reuse は禁止します。

| Type | Reuse 規則 |
|---|---|
| `CorrelationId` | command / event chain を超えて再利用しない |
| `ParticipantId` | room membership lifecycle を超えて再利用しない |
| `EndpointId` | endpoint lifecycle を超えて再利用しない |
| `PacketId` | packet lifecycle を超えて再利用しない |
| `AllocationId` | TURN allocation lifecycle を超えて再利用しない |
| `PermissionId` | TURN permission lifecycle を超えて再利用しない |
| `ChannelBindId` | TURN channel bind lifecycle を超えて再利用しない |
| `AuditEventId` | 再利用しない |
| `StartupRunId` | startup / wiring attempt を超えて再利用しない |
| `ConfigurationScopeRef` | configuration validation lifecycle を超えて再利用しない |

## 13. mapping 境界

external identity と core identity の trust mapping は core-owned policy が所有します。driver は external reference の decode / syntax validation / transport conversion だけを行います。entrypoints は mapping policy と driver implementation を wiring するだけであり、trusted core identity を発行しません。

trusted な `ParticipantId`、`SessionId`、`EndpointId`、`AllocationId`、`PermissionId`、`ChannelBindId` は core が発行したもの、または core が検証済みとして受理したものに限定します。driver 由来の `CorrelationId`、`RoomId`、`PacketId` は core validation と core-owned wrapping を通るまで untrusted reference です。core は accepted mapping result を opaque reference として扱います。regulated mapping は regulated 側が所有し、generic core は regulated mapping table を所有しません。

## 14. cross-plane identity / session binding

本節は「ある plane の成功や参照を、別 plane の同一主体・同一許可・同一 session として採用してよい条件」を固定します。個別 plane の state machine は各 plane が所有します。本節は cross-plane runtime 実装、実通信成功、media readiness を主張しません。

### 14.1 plane ごとの所有と規則

| Concern | Owner | 規則 |
|---|---|---|
| Signaling room / participant state | core/signaling | room membership は単体では SFU/TURN authorization ではない |
| SFU session / endpoint / stream state | core/sfu | endpoint admission には明示的 binding と SFU decision が必要 |
| TURN allocation / permission / channel bind state | core/turn | relay authorization には TURN lifecycle decision が必要 |
| ICE candidate relation | core/signaling + core/transport | candidate relay は connectivity や TURN permission を証明しない |
| secure media session relation | core/transport policy + driver observation | protection evidence は participant authorization を証明しない |
| cross-plane binding policy | core-owned typed policy | source/target plane、references、lifecycle、authorization relation |
| binding materialization | driver/entrypoint wiring を伴う core use case | driver-local implicit binding は不可 |
| evidence | reports | claim が plane を越えるとき binding class と references が必須 |

同一 `CorrelationId` は cross-plane binding ではありません。同一 token subject、entrypoint user ID、network address、ICE username fragment、endpoint name も cross-plane binding ではありません。

### 14.2 binding class（閉集合）

| Class | 意味 | 規則 |
|---|---|---|
| `no_cross_plane_binding_required` | target claim は single-plane のみ | cross-plane evidence を主張しない |
| `signaling_participant_binding` | Signaling room participant を target plane reference に bind | accepted Signaling participant state が必要 |
| `sfu_endpoint_binding` | SFU endpoint/session を Signaling participant/session context に bind | SFU endpoint admission decision が必要 |
| `turn_allocation_binding` | TURN allocation を許可された communication context に bind | TURN allocation decision と credential relation が必要 |
| `turn_permission_binding` | TURN permission/channel bind を許可された peer/relay context に bind | active allocation と permission decision が必要 |
| `ice_candidate_binding` | ICE candidate を room/participant と optional TURN relation に bind | candidate policy decision が必要 |
| `secure_media_session_binding` | secure media observation を SFU endpoint/session scope に bind | secure media session evidence class が必要 |
| `test_cross_plane_binding` | test 用の deterministic / fake binding | test evidence のみ |
| `implicit_binding_requested` | admitted binding policy なしに cross-plane relation を推測 | 拒否される |

新規 binding class は仕様の更新を要します。

### 14.3 binding 宣言規則

cross-plane binding は次を宣言しなければなりません。binding class / source plane / target plane / source reference type と lifecycle / target reference type と lifecycle / accepted authorization context relation / source plane の state precondition / target plane の state precondition / expiry・revocation behavior / command-scoped 時の replay・idempotency relation / audit event relation / audit evidence relation。

いずれかの必須 field が欠ける場合、cross-plane behavior は fail-closed とするか、当該 claim について close-not-claimed として記録しなければなりません。

### 14.4 非等価規則

次の観測はそれ自体では binding ではありません。Signaling join accepted / token verification accepted / authorization context mapped / ICE candidate relayed / TURN credential delivered / TURN allocation accepted / DTLS handshake observed / SRTP protection active / endpoint resolution succeeded / 同一 `CorrelationId` / 同一 external user/entrypoint/tenant/regulated subject。各々は後続 decision の入力にはなりますが、target plane の decision を置き換えません。

### 14.5 lifecycle 規則

binding は参照する全 lifecycle が valid である間のみ valid です。

| source / target relation | 必要な lifecycle 規則 |
|---|---|
| Signaling participant -> SFU endpoint | participant joined かつ endpoint admitted。leave/drain は新規 SFU action を無効化 |
| Signaling participant -> TURN allocation | participant/session policy と TURN credential relation が valid であり続ける |
| TURN allocation -> TURN permission/channel bind | allocation active かつ、必要箇所で permission/channel state active |
| ICE candidate -> TURN relay relation | relay candidate claim は claim 時に TURN allocation/permission relation を要する |
| secure media -> SFU forwarding | secure media protection state と SFU endpoint/route state の両方が valid |

ある plane の lifecycle expiry は別 plane を暗黙に mutate してはなりません。target plane は自身の state machine と cataloged reason を通じて reject または close しなければなりません。

### 14.6 failure mapping

| Failure | 必須 reason |
|---|---|
| binding class が admitted でない | `cross_plane_binding_not_admitted` |
| 必須 binding が欠ける | `cross_plane_binding_missing` |
| binding material が宣言 references に map できない | `cross_plane_binding_invalid` |
| source/target scope の衝突 | `cross_plane_binding_scope_conflict` |
| source または target lifecycle state が binding に valid でない | `cross_plane_binding_lifecycle_conflict` |
| binding lifetime または source relation が expire | `cross_plane_binding_expired` |
| binding replay/idempotency conflict 検出 | `cross_plane_binding_replay_detected` |
| target SFU participant/endpoint が admitted でない | `participant_not_admitted` または `target_unavailable` |
| target TURN allocation/permission が欠ける | `allocation_not_found` または `permission_not_found` |
| target secure media protection が active でない | `secure_media_protection_not_active` |

### 14.7 audit 規則

cross-plane binding decision は audit event type `cross_plane_binding_decision` を用います。event は `CorrelationId`、binding class、source plane、target plane、materialize 時の source/target reference、該当時の authorization context class、lifecycle state class、および rejected/expired/failed outcome の cataloged reason を持たなければなりません。

### 14.8 evidence 規則

cross-plane binding evidence は次を記録しなければなりません。binding class / source plane と target plane / materialize 時の source reference と target reference / source lifecycle state と target lifecycle state / authorization context relation / 関連する Signaling/SFU/TURN/ICE/secure media decision event references / command または procedure / working directory / expected outcome / actual outcome / 非成功の cataloged reason / close-not-claimed scope。single-plane evidence を cross-plane binding evidence として再利用してはなりません。

## 15. 禁止事項

- driver が aggregate state transition を所有する。
- entrypoints が domain decision を所有する。
- value object が external concrete type の wrapper になる。
- use case が `tokio`、`axum`、`sqlx`、`str0m`、browser/native SDK 型を参照する。
- domain service が audit sink / metrics exporter / DB schema を所有する。
- aggregate family を実装都合で追加し、仕様の更新なしで公開 API に出す。
- cross-plane binding を driver-local cache または implicit correlation として扱う。
- core identity が entrypoint user identity または regulated subject identity を意味する。
- client 提供 ID を trusted transport identity にする。
- driver または entrypoints が trusted core identity を発行する。
- identity に domain role や sensitive payload を埋め込む。
- lifetime を超えた identity reuse を許可する。
- Signaling join success を SFU endpoint admission として扱う。
- token verification / authorization context mapping を TURN/SFU binding として扱う。
- 同一 correlation ID を同一 participant/session/endpoint binding として扱う。
- ICE candidate relay を TURN allocation または connectivity proof として扱う。
- TURN credential delivery を active TURN allocation または permission として扱う。
- secure media handshake/protection を communication authorization として扱う。
- driver-local map が core-owned binding decision なしに participant/endpoint/allocation を bind する。
- ある plane の lifecycle expiry が別 plane を暗黙に mutate する。

## 16. fail-closed / 不変条件

- closed reason vocabulary にない domain failure を use case が返してはなりません。返せない場合は fail-closed です。
- cross-plane binding に必須 field が欠ける場合、fail-closed または close-not-claimed とします。
- core identity は lifetime 内で stable、超過 reuse は不可。
- core は external I/O 非依存（`core <- drivers <- entrypoints`）。
- identity の trust 発行は core のみ。driver/entrypoints は trusted core identity を発行しません。

## 17. 判断が崩れる条件（collapse conditions）

- domain rule が drivers または entrypoints に移る。
- core use case が external concrete type を受け取る。
- aggregate invariant が driver-local branch として実装される。
- application use case が composition root の代わりに driver selection を行う。
- closed reason vocabulary にない domain failure を use case が返す。
- use case result shape を driver が自由解釈する。
- idempotency or replay behavior が driver cache または SDK reconnect から推測される。
- cross-plane binding behavior が同一 correlation、external identity、driver-local state から推測される。
- core identity が entrypoint user identity または regulated subject identity を意味する。
- client 提供 ID を trusted transport identity にする。
- identity に domain role や sensitive payload を埋め込む。
- `StreamId` の external exposure 条件を public contract なしに実装判断へ委ねる。
- lifetime を超えた identity reuse を許可する。
- authorization context mapping を identity issuance として扱う。
- cross-plane binding class が implicit になる。
- source/target plane または reference type が欠ける。
- single-plane success を cross-plane success として用いる。
- binding lifecycle が expiry/revocation behavior を定義しない。
- driver-local cache が binding authority になる。
- cross-plane binding failure が free-text のみで記録される。
- cross-plane claim が binding evidence class を隠す。
