# core-domain-and-identity

Status: SSOT consolidated edition
Date: 2026-06-28 JST

## Purpose

This chapter internalizes, at a re-implementable level of detail, the arcRTC v0.2 Kernel core DDD domain model, aggregates, domain services, application use case boundaries, core-owned identity / reference, separation from external identity, correlation, and the cross-plane identity / session binding semantics spanning Signaling / SFU / TURN / ICE / secure media. This chapter does not fix implementation classes / structs; it fixes the responsibilities and invariants that MUST NOT be mixed inside core.

Dependency notation `A <- B` reads as "B depends on A". The Kernel layering is `core <- drivers <- entrypoints`, and core does not depend on external I/O.

## 1. Core Ownership Boundary

core owns the following.

- domain value object
- aggregate state
- domain service
- application use case
- core-owned port contract
- command / decision / event semantics
- connection to the closed reason vocabulary

core MUST NOT own (prohibited): external I/O, driver implementation, runtime, framework, DB, cloud SDK, browser/native types. These belong to drivers or entrypoints.

## 2. Tactical DDD Ownership

| Element | Owner | Rule |
|---|---|---|
| Value object | core | holds immutable semantics, equality, validation rule |
| Aggregate | core | holds state transition and invariant |
| Domain service | core | holds domain rule not confined to a single aggregate |
| Application use case | core | holds command orchestration, port calls, decision emission |
| Port | core | holds the abstract boundary to external implementation |
| Driver implementation | drivers | implements the port, holds external type conversion and I/O |
| Composition root | entrypoints | holds only implementation selection and dependency wiring |

## 3. Permitted Aggregate Families

The aggregate families permitted in v0.2 initial architecture are limited to the following. A new aggregate family MUST be introduced by a specification update before implementation.

| Family | Scope |
|---|---|
| Signaling room / participant | room state, participant state, command acceptance |
| SFU session / endpoint / route | media routing state and forwarding decision |
| TURN allocation / permission / channel bind | relay authorization lifecycle |
| Cross-plane binding scope | relation between Signaling participant, SFU endpoint/session, TURN allocation/permission, ICE, and secure media references |
| Audit chain scope | audit event ordering and hash-chain semantics |
| Configuration scope | startup / wiring policy acceptance |

## 4. Application Use Case Rule

An application use case operates in the following order.

1. Receive a core-owned command from a driver.
2. Validate the command's correlation / identity / idempotency / replay / version.
3. Delegate the decision to an aggregate or domain service.
4. Connect the decision reason to the closed reason catalog.
5. Produce the required port commands, audit events, and external response models.

An application use case MUST NOT receive external concrete types. It MUST NOT own driver-local retry, socket read/write, DB transaction, or runtime task scheduling. Its result shape MUST follow the core-owned result shapes (`UseCaseDecision` etc., internalized in chapter 04).

## 5. Domain Service Rule

A domain service holds pure domain rule only. When a domain service calls a port, that call is limited to a core-owned port contract explicitly injected from the application use case. It is prohibited for a domain service to directly reference a driver concrete implementation, runtime handle, DB connection, or network socket.

## 6. Validation Ownership Boundary

| Validation | Owner | Example |
|---|---|---|
| wire shape / decode | driver | JSON field presence, frame size, external enum mapping |
| identity / version / correlation | core | CorrelationId, command version, opaque reference stability |
| idempotency / replay | core | command identity, duplicate handling, replay window |
| domain invariant | core | room accepting join, route selectable, allocation active |
| external implementation readiness | driver/entrypoints | socket bind, DB DSN, exporter initialization |

drivers perform external shape validation and conversion validation. core performs domain validation and policy validation.

## 7. Identity Principle

The identity arcRTC core handles is an opaque reference for communication transport. It MUST NOT be inferred from core identity that it implies personhood, profession, medical role, business role, or tenant authority. core does not define user account, application user identity, or regulated identity.

## 8. Core-Owned Identity Types

| Type | Owner | Generated by | Lifetime | External exposure | Meaning |
|---|---|---|---|---|---|
| `CorrelationId` | core | driver-created untrusted input or core policy, accepted only after core validation | single command / event chain | yes | request / event trace |
| `RoomId` | core | caller-provided untrusted reference accepted only after core validation and wrapping | room lifecycle | yes | signaling room reference |
| `SessionId` | core | core policy | transport session lifecycle | yes | communication session reference |
| `ParticipantId` | core | core policy | room membership lifecycle | yes | opaque participant reference |
| `EndpointId` | core | core policy | SFU endpoint lifecycle | internal or controlled external | SFU endpoint reference |
| `StreamId` | core | core policy | media stream lifecycle | controlled external only through explicit Signaling/SFU contract | opaque media stream reference |
| `PacketId` | core | driver-created untrusted input or core policy, accepted only after core validation | packet lifecycle | no by default | packet decision correlation |
| `RouteId` | core | core policy | route decision lifecycle | no by default | SFU routing decision reference |
| `AllocationId` | core | core policy | TURN allocation lifecycle | no by default | TURN allocation reference |
| `PermissionId` | core | core policy | TURN permission lifecycle | no by default | TURN permission reference |
| `ChannelBindId` | core | core policy | TURN channel bind lifecycle | no by default | TURN channel binding reference |
| `AuditEventId` | core | core policy | audit event lifecycle | yes for audit | audit event reference |
| `CredentialRef` | core | driver conversion from external credential | credential verification lifecycle | no raw secret exposure | credential reference only |
| `StartupRunId` | core | entrypoints-provided untrusted startup reference accepted only after core validation, or core policy | single startup / wiring attempt | audit only | startup execution reference |
| `ConfigurationScopeRef` | core | entrypoints-provided untrusted configuration scope accepted only after core validation, or core policy | configuration validation lifecycle | audit only | opaque configuration scope reference |

Admission scope (rate limit / quota) MUST use core-owned opaque references and MUST NOT infer tenant/user/entrypoint role identity from these references. Authorization context MAY contribute typed policy input, but it MUST NOT redefine trusted core identity meaning.

## 9. Client Input Rule

Client-provided identifiers are untrusted input. Client input MAY request a `RoomId` or carry an external reference, but it does not become trusted identity without core validation and core-owned wrapping.

Prohibited:

- treating a client-provided participant ID as a trusted `ParticipantId`.
- equating a token subject with a `ParticipantId`.
- equating an entrypoint user ID with transport identity.
- equating a regulated subject ID with generic communication identity.

## 10. Opaque Reference Rule

A core identity that is externally exposed MUST be opaque. An opaque reference MUST NOT contain: user role, tenant role, medical role, facility identity, personally identifying payload, token secret, or media payload information.

## 11. External Exposure Rule

External exposure of core identity MUST be explicit per public contract surface.

| Type | Public exposure rule |
|---|---|
| `RoomId` | exposed only as opaque Signaling room reference |
| `ParticipantId` | exposed only as opaque room participant reference |
| `SessionId` | exposed only as opaque communication session reference |
| `StreamId` | exposed only when Signaling/SFU contract explicitly needs an opaque media stream reference |
| `EndpointId` | not public by default; controlled operational exposure only |
| `PacketId` | not public by default; diagnostic/audit correlation only if explicitly allowed |

`StreamId` MUST NOT encode media payload type, codec, participant role, tenant, regulated subject, or application user identity.

## 12. Stability Rule (lifetime and reuse)

identity is stable within its lifetime. Reuse beyond the lifetime is prohibited.

| Type | Reuse rule |
|---|---|
| `CorrelationId` | not reused beyond the command / event chain |
| `ParticipantId` | not reused beyond the room membership lifecycle |
| `EndpointId` | not reused beyond the endpoint lifecycle |
| `PacketId` | not reused beyond the packet lifecycle |
| `AllocationId` | not reused beyond the TURN allocation lifecycle |
| `PermissionId` | not reused beyond the TURN permission lifecycle |
| `ChannelBindId` | not reused beyond the TURN channel bind lifecycle |
| `AuditEventId` | not reused |
| `StartupRunId` | not reused beyond the startup / wiring attempt |
| `ConfigurationScopeRef` | not reused beyond the configuration validation lifecycle |

## 13. Mapping Boundary

The trust mapping between external identity and core identity is owned by core-owned policy. Drivers perform only decode / syntax validation / transport conversion of external references. entrypoints only wire mapping policy and driver implementation, and do not issue trusted core identity.

A trusted `ParticipantId`, `SessionId`, `EndpointId`, `AllocationId`, `PermissionId`, or `ChannelBindId` is limited to one that core issues or that core has accepted as validated. A driver-originated `CorrelationId`, `RoomId`, or `PacketId` remains an untrusted reference until it passes core validation and core-owned wrapping. core treats an accepted mapping result as an opaque reference. regulated mapping is owned on the regulated side, and generic core does not own a regulated mapping table.

## 14. Cross-Plane Identity / Session Binding

This section fixes the conditions under which "success or a reference in one plane MAY be adopted as the same subject, same authorization, or same session in another plane." Each plane's state machine is owned by that plane. This section does not claim cross-plane runtime implementation, real communication success, or media readiness.

### 14.1 Per-Plane Ownership and Rules

| Concern | Owner | Rule |
|---|---|---|
| Signaling room / participant state | core/signaling | room membership is not SFU/TURN authorization by itself |
| SFU session / endpoint / stream state | core/sfu | endpoint admission requires explicit binding and SFU decision |
| TURN allocation / permission / channel bind state | core/turn | relay authorization requires TURN lifecycle decision |
| ICE candidate relation | core/signaling + core/transport | candidate relay does not prove connectivity or TURN permission |
| secure media session relation | core/transport policy + driver observation | protection evidence does not prove participant authorization |
| cross-plane binding policy | core-owned typed policy | source/target plane, references, lifecycle, authorization relation |
| binding materialization | core use case with driver/entrypoint wiring | no driver-local implicit binding |
| evidence | reports | binding class and references required when claim crosses planes |

Same `CorrelationId` is not cross-plane binding. Same token subject, entrypoint user ID, network address, ICE username fragment, or endpoint name is not cross-plane binding.

### 14.2 Binding Classes (closed set)

| Class | Meaning | Rule |
|---|---|---|
| `no_cross_plane_binding_required` | target claim is single-plane only | cross-plane evidence not claimed |
| `signaling_participant_binding` | Signaling room participant is bound to a target plane reference | requires accepted Signaling participant state |
| `sfu_endpoint_binding` | SFU endpoint/session is bound to Signaling participant/session context | requires SFU endpoint admission decision |
| `turn_allocation_binding` | TURN allocation is bound to allowed communication context | requires TURN allocation decision and credential relation |
| `turn_permission_binding` | TURN permission/channel bind is bound to allowed peer/relay context | requires active allocation and permission decision |
| `ice_candidate_binding` | ICE candidate is bound to room/participant and optional TURN relation | requires candidate policy decision |
| `secure_media_session_binding` | secure media observation is bound to SFU endpoint/session scope | requires secure media session evidence class |
| `test_cross_plane_binding` | deterministic or fake binding for tests | test evidence only |
| `implicit_binding_requested` | cross-plane relation is inferred without admitted binding policy | rejected |

A new binding class requires a specification update.

### 14.3 Binding Declaration Rule

Cross-plane binding MUST declare: binding class; source plane; target plane; source reference type and lifecycle; target reference type and lifecycle; accepted authorization context relation; state precondition in source plane; state precondition in target plane; expiry/revocation behavior; replay/idempotency relation when command-scoped; audit event relation; audit evidence relation.

If any required field is absent, cross-plane behavior MUST fail closed or be recorded as close-not-claimed for the affected claim.

### 14.4 Non-Equivalence Rule

The following observations are not binding by themselves: Signaling join accepted; token verification accepted; authorization context mapped; ICE candidate relayed; TURN credential delivered; TURN allocation accepted; DTLS handshake observed; SRTP protection active; endpoint resolution succeeded; same `CorrelationId`; same external user/entrypoint/tenant/regulated subject. Each MAY be input to a later decision, but none replaces the target plane decision.

### 14.5 Lifecycle Rule

Binding is valid only while all referenced lifecycles remain valid.

| Source / target relation | Required lifecycle rule |
|---|---|
| Signaling participant -> SFU endpoint | participant joined and endpoint admitted; leave/drain invalidates new SFU actions |
| Signaling participant -> TURN allocation | participant/session policy and TURN credential relation must still be valid |
| TURN allocation -> TURN permission/channel bind | allocation active and permission/channel state active where required |
| ICE candidate -> TURN relay relation | relay candidate claim requires TURN allocation/permission relation when claimed |
| secure media -> SFU forwarding | secure media protection state and SFU endpoint/route state must both be valid |

Lifecycle expiry in one plane MUST NOT silently mutate another plane. The target plane MUST reject or close through its own state machine and cataloged reason.

### 14.6 Failure Mapping

| Failure | Required reason |
|---|---|
| binding class is not admitted | `cross_plane_binding_not_admitted` |
| required binding is absent | `cross_plane_binding_missing` |
| binding material cannot map to declared references | `cross_plane_binding_invalid` |
| source/target scope conflicts | `cross_plane_binding_scope_conflict` |
| source or target lifecycle state is not valid for binding | `cross_plane_binding_lifecycle_conflict` |
| binding lifetime or source relation expired | `cross_plane_binding_expired` |
| binding replay/idempotency conflict detected | `cross_plane_binding_replay_detected` |
| target SFU participant/endpoint is not admitted | `participant_not_admitted` or `target_unavailable` |
| target TURN allocation/permission is absent | `allocation_not_found` or `permission_not_found` |
| target secure media protection is not active | `secure_media_protection_not_active` |

### 14.7 Audit Rule

Cross-plane binding decisions use audit event type `cross_plane_binding_decision`. The event MUST carry `CorrelationId`, binding class, source plane, target plane, source reference, target reference when materialized, authorization context class when applicable, lifecycle state class, and cataloged reason for rejected/expired/failed outcomes.

### 14.8 Evidence Rule

Cross-plane binding evidence MUST record: binding class; source plane and target plane; source reference and target reference when materialized; source lifecycle state and target lifecycle state; authorization context relation; related Signaling/SFU/TURN/ICE/secure media decision event references; command/procedure; working directory; expected outcome; actual outcome; cataloged reason for non-success; close-not-claimed scope. Single-plane evidence MUST NOT be reused as cross-plane binding evidence.

## 15. Prohibitions

- a driver owns aggregate state transition.
- entrypoints own a domain decision.
- a value object becomes a wrapper of an external concrete type.
- a use case references `tokio`, `axum`, `sqlx`, `str0m`, or browser/native SDK types.
- a domain service owns audit sink / metrics exporter / DB schema.
- an aggregate family is added for implementation convenience and exposed in the public API without a specification update.
- cross-plane binding is treated as a driver-local cache or implicit correlation.
- core identity means entrypoint user identity or regulated subject identity.
- a client-provided ID is made trusted transport identity.
- a driver or entrypoints issue trusted core identity.
- domain role or sensitive payload is embedded in identity.
- identity reuse beyond the lifetime is allowed.
- Signaling join success is treated as SFU endpoint admission.
- token verification / authorization context mapping is treated as TURN/SFU binding.
- the same correlation ID is treated as the same participant/session/endpoint binding.
- ICE candidate relay is treated as TURN allocation or connectivity proof.
- TURN credential delivery is treated as active TURN allocation or permission.
- secure media handshake/protection is treated as communication authorization.
- a driver-local map binds participant/endpoint/allocation without a core-owned binding decision.
- lifecycle expiry in one plane silently mutates another plane.

## 16. Fail-Closed / Invariants

- A use case MUST NOT return a domain failure absent from the closed reason vocabulary; if it cannot, it is fail-closed.
- If a required field of cross-plane binding is absent, it is fail-closed or close-not-claimed.
- core identity is stable within its lifetime; reuse beyond it is not allowed.
- core does not depend on external I/O (`core <- drivers <- entrypoints`).
- Only core issues trust; drivers/entrypoints do not issue trusted core identity.

## 17. Collapse Conditions

- domain rule moves to drivers or entrypoints.
- a core use case receives an external concrete type.
- an aggregate invariant is implemented as a driver-local branch.
- an application use case performs driver selection instead of the composition root.
- a use case returns a domain failure absent from the closed reason vocabulary.
- a driver freely interprets the use case result shape.
- idempotency or replay behavior is inferred from driver cache or SDK reconnect.
- cross-plane binding behavior is inferred from same correlation, external identity, or driver-local state.
- core identity means entrypoint user identity or regulated subject identity.
- a client-provided ID is made trusted transport identity.
- domain role or sensitive payload is embedded in identity.
- the `StreamId` external exposure condition is left to implementation judgment without a public contract.
- identity reuse beyond the lifetime is allowed.
- authorization context mapping is treated as identity issuance.
- the cross-plane binding class is implicit.
- the source/target plane or reference type is absent.
- single-plane success is used as cross-plane success.
- the binding lifecycle does not define expiry/revocation behavior.
- a driver-local cache becomes the binding authority.
- cross-plane binding failure is recorded as free-text only.
- a cross-plane claim hides the binding evidence class.
